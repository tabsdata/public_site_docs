Custom Connectors

A custom connector is a Python package that contains the configuration classes and read or write code for an external system. Installing the package adds that system as a source for publishers or a destination for subscribers.

AI agents connected through the MCP Server can also write custom connectors.

File structure​

The following code uses an example for an sqlite connector.

Create a directory named sqlite_connector with the following files. The Python files belong in src/tabsdata_sqlite, which is the package users will import.

pyproject.toml
error.py
__init__.py
_plugin.py

pyproject.toml defines the package, its dependencies, and the entry points Tabsdata uses to find the connector.

error.py defines the errors reported when configuration is invalid or a read or write fails.

__init__.py defines the fields used in connection documents and Python functions.

_plugin.py implements the reads and writes, and registers the classes they use.

Build each file in the order shown. When a file has more than one step, append each code block to that file.

pyproject.toml​

Step 1aDefine the package and its dependencies

Add the package name and build settings to pyproject.toml. The name tabsdata-conn-sqlite is what pip installs; tabsdata_sqlite is what Python imports. The where = ["src"] setting tells setuptools where to find that Python package.

The Tabsdata dependency limits this connector to the 2.1 release series, since its classes and plugins use that release's API. SQLite is included in Python. For a system that needs an additional client library, add the library to dependencies.

pyproject.toml
1[build-system]
2requires = ["setuptools>=69"]
3build-backend = "setuptools.build_meta"
4 
2[project]
6name = "tabsdata-conn-sqlite"
7version = "0.1.0"
8description = "Tabsdata source and destination connector for SQLite databases."
9requires-python = ">=3.12"
10dependencies = [
11  "tabsdata>=2.1,<2.2",
12]
13 
3[tool.setuptools.packages.find]
15where = ["src"]
  • Uses setuptools to build the installable package.
  • The package name is used by pip. The Tabsdata dependency targets the 2.1 release series.
  • Finds tabsdata_sqlite under src/.
Step 1bDeclare the entry points Tabsdata will load

Add an entry point for the source and another for the destination. Each value names a Python module and an object in that module, separated by a colon.

The source entry point loads SQLITE_SRC from tabsdata_sqlite._plugin. The destination entry point loads SQLITE_DEST from the same module. These objects will be defined in step 4d, after the connection classes and plugins exist.

pyproject.toml · append
1[project.entry-points."tabsdatak.connectors"]
1src_sqlite = "tabsdata_sqlite._plugin:SQLITE_SRC"
2dest_sqlite = "tabsdata_sqlite._plugin:SQLITE_DEST"
  • Loads SQLITE_SRC, the source registration created in step 4d.
  • Loads SQLITE_DEST, the destination registration created in step 4d.

error.py​

Step 2aDefine the exception for failed reads and writes

In src/tabsdata_sqlite/error.py, create SqliteRuntimeException as a subclass of ConnException, the base class for connector errors. The plugins will raise this exception when a query or a write fails.

error.py
1from tabsdatak.conn.common.error import ConnException, ConnInitException
2from tabsdatak.error import ErrorCode, ErrorDef
3 
4 
1class SqliteRuntimeException(ConnException):
6  """A SQLite read or write failed."""
  • The base exception used by the read and write error codes in step 2b.
Step 2bAssign error codes to configuration and execution failures

Append SqliteErrorCode. Each ErrorDef associates an exception type with an error message.

Codes SQLITE_1 through SQLITE_4 belong to the configuration classes defined in the next file. The remaining codes use SqliteRuntimeException from step 2a and will be raised by the plugins in steps 4b and 4c. A placeholder such as {table} is filled with the value passed to .exception().

error.py · append
1class SqliteErrorCode(ErrorCode):
1  SQLITE_1 = ErrorDef(ConnInitException, "SqliteSrcConn validation failed")
3  SQLITE_2 = ErrorDef(ConnInitException, "SqliteDestConn validation failed")
4  SQLITE_3 = ErrorDef(ConnInitException, "SqliteSrc validation failed")
5  SQLITE_4 = ErrorDef(ConnInitException, "SqliteDest validation failed")
2  SQLITE_5 = ErrorDef(SqliteRuntimeException, "SQLite query {index} failed")
3  SQLITE_6 = ErrorDef(
8      SqliteRuntimeException,
9      "SQLite received {slots} table(s) for {tables} target table(s)",
10  )
11  SQLITE_7 = ErrorDef(SqliteRuntimeException, "SQLite write to {table} failed")
  • The decorators in steps 3b and 3c use these codes when a field fails validation.
  • Raised by read_in in step 4b with the failed query's index.
  • Raised by write_out in step 4c for a table count mismatch or a failed write.

__init__.py​

__init__.py defines the classes users import from tabsdata_sqlite. Connection classes define how to reach the database. Source and destination classes define what a function reads or writes.

Step 3aImport the base classes and define the shared field types

In src/tabsdata_sqlite/__init__.py, import the Tabsdata classes and the error codes from step 2b.

StrOrSecretSpec accepts a string or a secret. The resolve helper returns the string value so the plugin can open the database file. TableName restricts destination table names to letters, numbers, and underscores, starting with a letter or underscore.

__init__.py
1from typing import Annotated, Literal
2 
3from pydantic import StringConstraints
4 
5import tabsdatak._api as _api
6from tabsdatak.api import Dest, Secret, Src, StrOrSecretSpec
7from tabsdatak.spi import Conn
1from tabsdata_sqlite.error import SqliteErrorCode
9 
10 
2TableName = Annotated[str, StringConstraints(pattern=r"^[A-Za-z_][A-Za-z0-9_]*$")]
12 
13 
3def resolve(spec: StrOrSecretSpec) -> str:
15  return spec.value() if isinstance(spec, Secret) else spec
  • Imports the codes defined in step 2b.
  • Constrains the destination's tables field in step 3c.
  • Returns the database path used by connect in step 4a.
Step 3bDefine the fields stored in a connection

Append SqliteSrcConn and SqliteDestConn, both derived from Tabsdata's Conn class. Each declares a required path field. When a user creates a connection document, that field becomes spec.path, and the document is attached to a collection.

The @_api.dataclass decorator creates the initializer and validates the field values. Its first argument selects the error code from step 2b, so invalid source connection settings raise SQLITE_1. The kw_only=True argument requires named arguments, such as SqliteSrcConn(path="/data/shop.db").

The source and destination have separate connection classes so Tabsdata can associate each connection with the appropriate plugin.

__init__.py · append
1@_api.dataclass(SqliteErrorCode.SQLITE_1, kw_only=True)
2class SqliteSrcConn(Conn):
3  """Connection to the SQLite database a publisher reads."""
4 
5  path: StrOrSecretSpec
6 
7 
2@_api.dataclass(SqliteErrorCode.SQLITE_2, kw_only=True)
9class SqliteDestConn(Conn):
10  """Connection to the SQLite database a subscriber writes."""
11 
12  path: StrOrSecretSpec
  • Defines spec.path in the source connection document. SQLITE_1 comes from step 2b; kw_only=True requires named arguments.
  • Defines spec.path in the destination connection document. The two connection classes identify which plugin uses the path.
Step 3cDefine the fields a function declares

Append SqliteSrc and SqliteDest. A publisher uses SqliteSrc(queries=[...]) in its source= argument. The query results become the publisher's input data in the same order as the queries.

A subscriber uses SqliteDest(tables=[...]) in its destination= argument. The table names identify the SQLite tables that receive the subscriber's returned data, in order. The if_table_exists field accepts "append" or "replace" and defaults to "replace".

Both classes use the validation decorator from step 3b with their own error codes. The destination also uses the TableName constraint from step 3a.

__init__.py · append
1@_api.dataclass(SqliteErrorCode.SQLITE_3, kw_only=True)
2class SqliteSrc(Src):
3  """Queries a publisher runs against SQLite."""
4 
5  queries: list[str]
6 
7 
2@_api.dataclass(SqliteErrorCode.SQLITE_4, kw_only=True)
9class SqliteDest(Dest):
10  """SQLite tables that receive a subscriber's returned data."""
11 
12  tables: list[TableName]
13  if_table_exists: Literal["append", "replace"] = "replace"
  • The publisher supplies queries through source=SqliteSrc(...). The database path comes from its collection's connection.
  • The subscriber supplies tables and if_table_exists through destination=SqliteDest(...). TableName was defined in step 3a.

SqliteSrcConn and SqliteSrc get their values from different places. The connection document supplies the database path for the collection, while the publisher supplies the queries for that function. At execution time, Tabsdata passes both objects to the source plugin.

The destination follows the same arrangement: its connection supplies the database path, and the subscriber supplies the target tables and write behavior.

_plugin.py​

The plugin receives the configuration defined in __init__.py and performs the database operations. A source plugin reads data before the publisher's Python function runs. A destination plugin writes the data returned by the subscriber's Python function.

Step 4aOpen the database using the connection's path

In src/tabsdata_sqlite/_plugin.py, import the classes from steps 3b and 3c and add a shared connect helper. The helper reads conn.path and calls resolve from step 3a to obtain its value.

_plugin.py

11  SrcPlugin,

14  TableFileSpec,
15  TableMode,
16)
1from tabsdata_sqlite import (
18  SqliteDest,
19  SqliteDestConn,
20  SqliteSrc,
21  SqliteSrcConn,
22  resolve,
23)

2def connect(conn: SqliteSrcConn | SqliteDestConn) -> sqlite3.Connection:
28  return sqlite3.connect(resolve(conn.path))
  • Imports the connection, source, and destination classes from steps 3b and 3c.
  • Uses resolve from step 3a to read conn.path and open SQLite.
note

The database path is resolved on the machine running the function. The SQLite file must be accessible there, including when functions run on separate workers.

Step 4bRead the queries declared by the source

Append SqliteSrcPlugin and implement read_in. Tabsdata passes the collection's SqliteSrcConn as conn and the publisher's SqliteSrc as src. These are the classes from steps 3b and 3c.

Use connect from step 4a to open the database, then run each query in src.queries. Write each result to a Parquet file in ctx.work_dir and return a list containing one TableFileInput for each query. The outer list preserves query order; each inner list contains the files for one result.

If a query fails, raise SQLITE_5 from step 2b with the query's index and the original exception.

_plugin.py · append
1class SqliteSrcPlugin(SrcPlugin[SqliteSrcConn, SqliteSrc]):
1  def read_in(
3      self,
4      ctx: SrcPluginCtx,
5      conn: SqliteSrcConn,
6      src: SqliteSrc,
7  ) -> list[list[TableFileInput]]:
8      con = connect(conn)
9      try:
10          slots = []
2          for index, query in enumerate(src.queries):
12              try:
13                  frame = pl.read_database(query, con)
14              except Exception as e:
15                  raise SqliteErrorCode.SQLITE_5.exception(cause=e, index=index)
3              parquet = Path(ctx.work_dir) / f"{index}.parquet"
17              frame.write_parquet(parquet)
18              slots.append([TableFileInput(file=parquet)])
19          return slots
20      finally:
21          con.close()
  • Tabsdata supplies the collection's connection as conn and the publisher's settings as src.
  • Reads src.queries from step 3c and raises SQLITE_5 from step 2b if a query fails.
  • Returns one Parquet file per query in the original query order.
Step 4cWrite the subscriber's results to the destination tables

Append SqliteDestPlugin and implement write_out. Tabsdata passes the destination connection as conn, the subscriber's SqliteDest as dest, and the returned data as Parquet file references in tables.

Match each file with a target name in dest.tables, the field from step 3c. A None file reference means the subscriber returned no new data for that position, so the plugin skips it. For each remaining file, read the rows and either replace the target table or append to it, according to dest.if_table_exists.

The table count check raises SQLITE_6 from step 2b. A failed write raises SQLITE_7 with the target table name. The explicit BEGIN includes table creation and replacement in the SQLite transaction, so a failed write rolls back those changes along with the inserted rows.

_plugin.py · append
1class SqliteDestPlugin(DestPlugin[SqliteDestConn, SqliteDest]):
2  def write_out(
3      self,
4      ctx: DestContext,
5      conn: SqliteDestConn,
6      dest: SqliteDest,
7      tables: list[TableFileSpec],
8  ) -> None:
1      if len(tables) != len(dest.tables):
10          raise SqliteErrorCode.SQLITE_6.exception(
11              slots=len(tables), tables=len(dest.tables)
12          )
13 
14      con = connect(conn)
15      try:
2          with con:
17              con.execute("BEGIN")
18              for table, parquet in zip(dest.tables, tables):
3                  if parquet is None:
20                      continue
21                  try:
4                      frame = pl.read_parquet(parquet)
23                      columns = ", ".join(
24                          '"' + c.replace('"', '""') + '"' for c in frame.columns
25                      )
26                      if dest.if_table_exists == "replace":
27                          con.execute(f'DROP TABLE IF EXISTS "{table}"')
28                      con.execute(
29                          f'CREATE TABLE IF NOT EXISTS "{table}" ({columns})'
30                      )
31                      marks = ", ".join("?" for _ in frame.columns)
32                      con.executemany(
33                          f'INSERT INTO "{table}" ({columns}) VALUES ({marks})',
34                          frame.iter_rows(),
35                      )
5                  except Exception as e:
37                      raise SqliteErrorCode.SQLITE_7.exception(cause=e, table=table)
38      finally:
39          con.close()
  • Matches the returned file count to dest.tables from step 3c.
  • Includes table creation and replacement in the transaction.
  • A None file reference means the subscriber returned no data for that position.
  • Uses dest.if_table_exists from step 3c to replace the target table or append rows.
  • Uses SQLITE_7 from step 2b and includes the destination table name.
Step 4dRegister the connection, configuration, and plugin classes together

Append SQLITE_SRC and SQLITE_DEST. Each registration associates a connection class from step 3b, a source or destination class from step 3c, and the plugin that uses them from steps 4b and 4c.

The object names must match the entry points in step 1b. When Tabsdata loads SQLITE_SRC, for example, the registration tells it to use SqliteSrcPlugin for SqliteSrc with a SqliteSrcConn connection.

_plugin.py · append
1SQLITE_SRC = SrcDef(
2  conn=SqliteSrcConn,
3  type_="sqlite-sql-in",
4  system="SQLite",
5  src_version="v1",
6  src=SqliteSrc,
7  table_mode=TableMode.SINGLE,
8  cardinality=lambda src: len(src.queries),
9  plugin=SqliteSrcPlugin,
10  explorer=None,
11  icon=None,
12)
13 
2SQLITE_DEST = DestDef(
15  conn=SqliteDestConn,
16  type_="sqlite-sql-out",
17  system="SQLite",
18  dest_version="v1",
19  dest=SqliteDest,
20  cardinality=lambda dest: len(dest.tables),
21  plugin=SqliteDestPlugin,
22  explorer=None,
23  icon=None,
24)
  • Binds the source classes from step 3 to the plugin from step 4b. This object is loaded by src_sqlite in step 1b.
  • Binds the destination classes from step 3 to the plugin from step 4c. This object is loaded by dest_sqlite in step 1b.

type_ is the registration's identifier and must be unique across installed connectors. It is separate from the connection document's type, which names the Python connection class.

cardinality gives the number of table positions: one per query for the source and one per target table for the destination. TableMode.SINGLE declares that the source returns one file per position, matching the return value in step 4b. This connector does not implement an explorer or provide an icon, so both are set to None.

Installing a connector​

The connector package must be available where tdk runs to validate connections and register functions. It must also be installed in the server's function environment to execute those functions.

Step 5aInstall the package where tdk runs

From the directory containing sqlite_connector, run:

pip install ./sqlite_connector
Step 5bInstall the package in the server's function environment

Make the package available to the server, for example through a Git repository. Replace <org> and <repo> with the repository that contains sqlite_connector, then add the package to a requirements file:

connectors.txt
tabsdata-conn-sqlite @ git+https://github.com/<org>/<repo>.git#subdirectory=sqlite_connector

Update the function environment and restart the instance. The environment update stops the instance.

tdkserver venv update --name fn --requirements connectors.txt
tdkserver start

The requirements file replaces the environment's current list of complementary packages. Include every complementary package the server still needs.

Using the connector​

Step 6aSet the connection fields and attach each connection to a collection

Create connection documents for the source and destination. The type field selects a connection class from step 3b, and spec.path supplies the required path field. The str: prefix represents a literal string in the connection document.

conn-sqlite-in.yaml
kind: connectionDef
apiVersion: '1.0'
type: tabsdata_sqlite:SqliteSrcConn
spec:
  path: str:/data/shop.db
conn-sqlite-out.yaml
kind: connectionDef
apiVersion: '1.0'
type: tabsdata_sqlite:SqliteDestConn
spec:
  path: str:/data/warehouse.db

The source database must already contain the customers and orders tables used by the publisher. The destination database is created on first use if it does not exist; its parent directory must exist and be writable.

Attach the source connection to shop in the sources group, and the destination connection to warehouse in the destinations group:

tdk collection create --name shop --group sources --conn-file conn-sqlite-in.yaml
tdk collection create --name warehouse --group destinations --conn-file conn-sqlite-out.yaml
Step 6bSet the source fields in a publisher

Create pub_shop.py and set queries, the field defined on SqliteSrc in step 3c. The source plugin from step 4b reads the query results before pub_shop runs. The function returns those results into the customers and orders Tabsdata tables.

pub_shop.py
from tabsdatak.api import publisher, TableFrameSpec
from tabsdata_sqlite import SqliteSrc


@publisher(
    source=SqliteSrc(queries=["SELECT * FROM customers", "SELECT * FROM orders"]),
    output_tables=["customers", "orders"],
)
def pub_shop(
    customers: TableFrameSpec, orders: TableFrameSpec
) -> tuple[TableFrameSpec, TableFrameSpec]:
    return customers, orders

Register the publisher in shop. Its connection comes from the shop collection created in step 6a.

tdk fn register --coll shop --path pub_shop.py::pub_shop
Step 6cSet the destination fields in a subscriber

Create sub_warehouse.py and set tables and if_table_exists, the fields defined on SqliteDest in step 3c. The subscriber reads shop/customers and shop/orders, then returns the data to the destination plugin from step 4c.

Using "replace" drops and recreates the named SQLite tables on each write. Use "append" to keep existing rows and insert the returned rows.

sub_warehouse.py
from tabsdatak.api import subscriber, TableFrameSpec
from tabsdata_sqlite import SqliteDest


@subscriber(
    destination=SqliteDest(tables=["customers", "orders"], if_table_exists="replace"),
    input_tables=["shop/customers", "shop/orders"],
)
def sub_warehouse(
    customers: TableFrameSpec, orders: TableFrameSpec
) -> tuple[TableFrameSpec, TableFrameSpec]:
    return customers, orders

Register the subscriber in warehouse so it uses that collection's destination connection.

tdk fn register --coll warehouse --path sub_warehouse.py::sub_warehouse
