Getting Started

Get Tabsdata running on your own computer in a few minutes. This is a lightweight local setup that requires no admin or root privileges.

By the end you'll have a running Tabsdata server and a small working dataflow that publishes, transforms, and subscribes data.

Before you start​

You need:

  • One of these operating systems:
    • Linux (x86) - Ubuntu 24, Debian 12, Fedora 42
    • macOS (Apple Silicon) - OSX Tahoe
    • Windows (x86) - Windows 11
  • Python 3.12
  • Recommended: an LLM API key from Anthropic or OpenAI. It's optional, but it turns on Tabsdata's AI features (the living semantic catalog and the agent).

Set your key as an environment variable so the next steps can use it:

  • macOS / Linux
  • Windows (PowerShell)
# set the one you have
export ANTHROPIC_KEY="sk-ant-..."
export OPENAI_KEY="sk-..."
$env:ANTHROPIC_KEY = "sk-ant-..."
$env:OPENAI_KEY = "sk-..."

1. Create a clean Python 3.12 environment​

Use whichever tool you already have: create the environment, then activate it.

  • conda
  • uv
  • pyenv
conda create -n tabsdata python=3.12 -y
conda activate tabsdata
uv venv --python 3.12 .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pyenv install 3.12
pyenv local 3.12
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

2. Install Tabsdata​

pip install "tabsdata[all]"

3. Start the server​

tdkserver quickstart configures and starts a local Tabsdata instance. It runs in the foreground and keeps running. That's normal. Leave it open and use a new terminal for the following steps.

Without an LLM API key:

tdkserver quickstart

With an LLM API key:

# Anthropic
tdkserver quickstart --anthropic-key $ANTHROPIC_KEY
# OpenAI
tdkserver quickstart --openai-key $OPENAI_KEY

4. Check it's running​

In your new terminal:

tdkserver status

5. Log in​

tdk login --server localhost --user admin --password tabsdata

6. Get the example project​

tdk examples extract --name quickstart --dir qs-example

This creates a qs-example/ folder with three functions: input.py (publisher qs_pub), transform.py (transformer qs_tfr), and output.py (subscriber qs_sub). It also includes two connection files, conn-input.yaml and conn-output.yaml.

7. Build and run the dataflow​

You'll build a small end-to-end dataflow across your three collections and run it:

  • Publish: qs_pub reads persons.csv and lands it as a table in the input collection.
  • Transform: qs_tfr adds a full_name column and drops age, producing a new table in the dataprod collection.
  • Subscribe: qs_sub writes that table out as JSON Lines through the output collection.

Create the project, add the three collections, register one function in each, then trigger the publisher. Tabsdata runs the transformer and subscriber automatically.

# Create the project and make it the default for the commands below
tdk project create --name quickstart
tdk pin set --proj quickstart

# Collections: a source (input), a transformation (dataprod), a destination (output)
tdk collection create --name input    --group sources      --conn-file qs-example/conn-input.yaml
tdk collection create --name dataprod --group default
tdk collection create --name output   --group destinations --conn-file qs-example/conn-output.yaml

# Register one function per collection
tdk fn register --coll input    --path qs-example/input.py::qs_pub
tdk fn register --coll dataprod --path qs-example/transform.py::qs_tfr
tdk fn register --coll output   --path qs-example/output.py::qs_sub

# Run it
tdk fn trigger --coll input --name qs_pub

The data has been written to the qs-example/output-data/ directory.

A few things worth knowing:

  • tdk pin set --proj quickstart makes quickstart the default project, so you don't repeat it on every command. To target a different project for a single command, add --proj <name>.
  • Every collection belongs to a group: sources for inbound data, destinations for outbound, and default for in-server transformations. For a source or destination collection, the group must match the connection in --conn-file.

8. Open the UI​

Go to http://localhost:2457 and log in with admin / tabsdata. You'll see your project, its collections, and the tables the flow just produced.
