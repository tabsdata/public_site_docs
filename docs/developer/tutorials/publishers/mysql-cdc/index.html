Publish data from MySQL CDC

Before you begin

Quickstart a Server or Start a Server
Create a Project
note

The MySQL CDC connector needs a database driver that Tabsdata cannot redistribute. See Installing Third-Party Database Drivers for how to declare it during installation.

The MySQL CDC publisher captures row-level changes (inserts, updates, deletes) from a MySQL database by reading its binary log (binlog) in real time. A long-lived stream worker follows the binlog and hands a flushed batch to the publisher on each rollover, so this uses @stream_publisher rather than @publisher.

What you’ll do

  1. Configure a connection to MySQL
  2. Write and Register the Stream Publisher

Configure a connection to MySQL​

Step 1Generate a connection template
tdk connection template --type mysql-cdc --file conn-mysql-cdc.yaml
Step 2Fill in the URI and credentials, and bind it to a collection
tdk collection create --name sales_cdc --group sources --conn-file conn-mysql-cdc.yaml

The connection holds the URI and credentials for MySQLCdcStreamSrcConn, which is separate from the batch MySQLSrcConn connector: it also reserves a server_id, the replica identifier the binlog stream uses. Each concurrent CDC connection against the same MySQL server needs a distinct server_id.

Write and Register the Stream Publisher​

Step 3Build the stream publisher file locally
read_sales_changes.py
1from tabsdatak.api import stream_publisher, TableFrameSpec, TableFramesSpec
2from tabsdatak.conn.mysql import MySQLCdcStreamSrc
3 
4 
5@stream_publisher(
6  source=MySQLCdcStreamSrc(
1      tables=["sales.orders", "sales.customers"],
2      start_from="tail",
9  ),
3  flush_interval_mins=2,
4  output_tables=["orders_changes", "customers_changes"],
12)
5def read_sales_changes(orders, customers):
6  return (orders[0], customers[0])
  • Qualified schema.table names to track.
  • "tail" begins at the current binlog position and never backfills.
  • Fallback rollover window in whole minutes if the binlog's own threshold has not fired.
  • One output table per tracked table, in the same order.
  • One TableFramesSpec parameter per source slot, always array mode. No ctx parameter.
  • One frame per output table, the same order as output_tables.

start_from also accepts "head" to begin at the oldest retained binlog, or an explicit GtidPosition(gtid=...), BinlogPosition(file=..., pos=...), or TimestampPosition(ts=...). A stream publisher takes no trigger_by and must not declare a ctx parameter — it runs inside the runtime's stream loop rather than per-transaction.

Step 4Register the stream publisher into the collection
tdk fn register --coll sales_cdc --path read_sales_changes.py::read_sales_changes

Rollover and buffering​

Rollover fires on whichever comes first: flush_interval_mins, or a threshold set via src_cfg, a config mapping over allowed CDC keys:

src_cfg keyDefaultDescription
tabsdata.cdc.buffer.max_rows10,000Flush to the working directory when row count in memory reaches this limit.
tabsdata.cdc.buffer.max_bytesNoneFlush when byte size in memory reaches this limit.
tabsdata.cdc.buffer.max_secs60Flush when this many seconds have elapsed since the last flush.
tabsdata.cdc.trigger.max_rowsNoneStage when total rows on disk reach this limit.
tabsdata.cdc.trigger.max_bytesNoneStage when total bytes on disk reach this limit.
tabsdata.cdc.trigger.max_secs60Stage when this many seconds have elapsed since the last stage.
tabsdata.cdc.poll_interval_seconds1Seconds between polling cycles when no new events are available.
mysql.cdc.blocking_timeout_seconds1Timeout in seconds for blocking reads from the binlog stream.
mysql.cdc.logging_level—Log level for the binlog reader.
source=MySQLCdcStreamSrc(
    tables=["sales.orders"],
    start_from="tail",
    src_cfg={"tabsdata.cdc.buffer.max_rows": 5000},
)

Output row shape​

columns_format (default "columns", or "struct" / "map") and flatten_columns (default True) control how the new — and, where present, old — column values lay out on each emitted change row.

Limitations​

  • TRUNCATE TABLE operations are not captured.
  • All tables must exist in the source database before the stream publisher is registered. Tables created afterward are not captured.
  • Schema changes on tracked tables (ALTER TABLE, ADD COLUMN, DROP COLUMN) are picked up automatically.

MySQL Setup to Enable CDC​

Refer to the MySQL documentation for comprehensive and up-to-date configuration instructions.

Server Configuration​

Add the following to your MySQL configuration file (my.cnf or my.ini) and restart the server:

[mysqld]
server-id                = 1
log_bin                  = mysql-bin
binlog_format            = ROW
binlog_row_image         = FULL
gtid_mode                = ON
enforce_gtid_consistency = ON
ParameterDescription
server-idEnables binary logging with a unique server identifier.
binlog_format = ROWRow-based format captures individual column values rather than SQL statements.
binlog_row_image = FULLLogs all columns for every change, not just modified ones.
gtid_mode = ONRequired for resuming from a precise position across server restarts.

Create a CDC User​

CREATE USER 'cdc_user'@'%' IDENTIFIED BY 'cdc_password';
GRANT REPLICATION SLAVE, REPLICATION CLIENT ON *.* TO 'cdc_user'@'%';
GRANT SELECT ON sales.* TO 'cdc_user'@'%';
FLUSH PRIVILEGES;

REPLICATION SLAVE and REPLICATION CLIENT are the minimum privileges needed to connect as a binlog reader. SELECT is required for the initial table schema discovery.
